# Архитектура

Документ для тех, кто будет менять код. Пользовательская часть — в [README](../README.md).

## Карта проекта

```
src/
  index.ts, App.tsx           точка входа: <Editor><AudioContext/></Editor>
  index.sass                  токены темы (цвета, шрифты, размеры) и базовые стили
  components/
    node-editor/              универсальный нодовый редактор, про звук ничего не знает
    audio-context/            всё про звук: ноды, порты, worklet'ы, панели, сессия, блоки
      nodes/                  по файлу на ноду
      blocks/                 Group, Group Input/Output, сворачивание и разворачивание
      lib/                    BaseNode, BasePort, SignalNode, UI-кит, defineWorklet
      worklet/                AudioWorklet-процессоры
      ports/                  AudioPort, SignalPort
      views/                  меню, транспорт, панель проекта, сессия, отладка
      examples/               демо-проекты (строки формата v0 и v1)
      _nodes.ts, _groups.ts   реестр нод и категорий
      legacyNodeIds.ts        замороженная таблица для формата v0
    canvas/                   <Canvas> с draw/loop
  library/                    мелкие независимые модули: media, midi, expression, base64, gzip…
docs/                         этот файл и ROADMAP
```

## Редактор (`node-editor`)

Редактор — это дерево React-компонентов-классов. Каждый из них отдаёт себя потомкам через контекст:

```
NodeHud > NodeMap > NodeLayers > NodeList > NodeLines > NodeSelection > NodeProject > NodeItem > NodePort
```

- `@provide()` кладёт экземпляр в контекст, `@inject(() => X)` достаёт ближайший `X` (поле заполняется во время render), `useInject(X)` — то же в функциональных компонентах. Всё это из `@vicimpa/react-decorators`.
- `@reactive()` + `@prop` превращают поля класса в сигналы (`@vicimpa/decorators`). **`@prop` работает, только если на том же классе стоит `@reactive()`**. Подкласс не должен заново объявлять реактивное поле: при `useDefineForClassFields` такое объявление затрёт аксессор.
- Поведение вынесено в плагины: `@connect(detectDrag, detectResize, …)`. Плагин — функция `(ctx) => dispose`, она запускается после монтирования.
- **NodeMap** — камера (`x`, `y`, `s`) и пересчёт координат страницы в координаты карты (`map.offset(pageXY)`).
- **NodeProject** — список нод проекта (`store`) и сериализация: `serialize` / `load` / `paste`, хуки `exportData` / `importData`.
- **NodeLines** хранит связи `[from, to]` и вызывает `onConnect` / `onDisconnect` у портов.
- **Фокус.** Горячие клавиши (Delete, Ctrl+A/C/X/V/D) слушают `window`, но срабатывают только у верхнего редактора из стека `focusedMaps`. Корневой редактор встаёт в стек сам, вложенный (`<Editor nested>`) — только когда открыт.

## Ноды (`audio-context`)

Нода — это класс, наследник `BaseNode`:

```tsx
@name('Gain')            // id типа: сохраняется в проекты, НЕ МЕНЯТЬ
@group('effect')         // категория: цвет и раздел меню
@icon(Volume1)           // значок lucide в заголовке и меню
export default class extends BaseNode {
  #gain = new GainNode(ctx);

  @store _gain = new SignalNode(this.#gain.gain, { min: 0, max: 1.5 });

  input = <AudioPort value={this.#gain} />;
  output = <AudioPort value={this.#gain} output />;

  _view = () => <Range label="Gain" accuracy={2} value={this._gain} />;
}
```

- `input` и `output` — строки портов основной обработки, `_view` — тело ноды.
- `_connect` — код при монтировании, он возвращает функцию очистки. Там подключаются аудио-узлы, подписки и таймеры.
- `@store` помечает поля, которые сохраняются в проект. Если в поле Signal или SignalNode, сохраняется `.value`.
- **AudioPort** держит `AudioNode`, **SignalPort** — `SignalNode`. Соединять можно любые сочетания, логика в `_onConnect` / `_onDisconnect`.
- **SignalNode** — `Signal<number>` поверх `ConstantSourceNode`. Он привязывается к `AudioParam` и даёт значение на частоте звука. Пока к нему не подключён провод, значение берётся из UI. Когда провод подключён, UI показывает пришедший сигнал: его читает AnalyserNode на каждом кадре.
- **UI-кит** (`lib/`): `Row` (строка «порт · подпись · контрол»), `Range`, `Number`, `Select`, `Toggle`, `MediaSelect`, `NumberInput`, `TextInput`. Стили лежат в `styles.module.sass`. Цвета берутся из CSS-переменных: `--accent` — цвет категории, его ставит `BaseNode`. На canvas цвет категории даёт `accentOf(canvas)`.
- Поля ввода внутри ноды не пропускают нажатия клавиш наружу (см. `NodeItem`), поэтому Backspace в поле не удалит ноду.

## Worklet'ы

- `defineWorklet({ params, props, context, loop })` собирает исходник процессора, вызывая `toString()` у метода `loop`. Поэтому **внутри `loop` нельзя обращаться к замыканиям и импортам**: только к `this` и глобальным объектам (`Math` и т. п.).
- Экземпляры переиспользуются через пул. `destroy()` возвращает узел в пул и шлёт `[RESET]`, чтобы процессор вернул `context` к исходному состоянию. `[STOP]` останавливает процессор навсегда.
- `defineRuntimeWorklet` (`lib/runtimeWorklet.ts`) регистрирует процессор во время работы из сгенерированного кода; так работают Expression и скомпилированные блоки. Код генерирует только `library/expression`: tokenizer → Pratt-парсер → AST → codegen по белым спискам. **Пользовательский текст никогда не попадает в `eval`, `Function` или исходник worklet'а напрямую.**

## Формат проекта

Проект — это строка: буфер обмена, ссылка `#p=`, файл `.wnodes`, автосохранение.

| Версия | Вид | Тип ноды |
|---|---|---|
| v0 | `base64(gzip(pack))` | индекс в `legacyNodeIds` |
| v1 | `wn1:` + `base64(gzip(pack))` | строковый id (`@name`) |

В пакете (`@vicimpa/data-pack`) хранятся:
- `nodes` — типы нод;
- `connect` — связи `[[нода, порт], [нода, порт]]`;
- `configs` — значения `@store` и позиции;
- `media` — вшитые файлы (только v1).

Кодек лежит в `node-editor/node-project/utils/projectCodec.ts`. Пишем всегда v1, читаем обе версии.

### Правила совместимости

Их нарушение молча ломает чужие сохранённые проекты.

1. **`@name` ноды не меняется никогда.** Отображаемое имя можно менять: заголовок берётся из имени класса, но его можно переопределить.
2. **Поля с `@store` не переименовываются.** Если нужно, читайте старое имя в сеттере.
3. **`legacyNodeIds.ts` не меняется.** Новые ноды туда не добавляются.
4. **Порядок портов — тоже часть формата.** Связь хранит номер порта в `sortPorts` ноды. Порты сортируются так: сначала входы, потом выходы; внутри — по типу порта; затем по порядку монтирования. Новые порты добавляйте в конец своей группы.

`npm test` проверяет все демо: что они читаются, что каждый сохранённый ключ есть среди `@store`-полей класса ноды, что набор `@store`-ключей не изменился (снапшот), что они переживают круговой цикл через v1 и что каждый legacy-id совпадает с `@name` какого-то класса.

## Сессия (`views/session`)

- **Автосохранение** раз в 2 с и после каждой замены проекта: `localStorage['w-nodes:autosave']` = `{ text, view }`.
- Любая замена проекта (демо, ссылка, файл, New) сначала откладывает текущий проект в `w-nodes:previous`.
- При старте: `#p=…` → демо по `#имя` → автосохранение. После загрузки по ссылке hash убирается, чтобы перезагрузка не затёрла правки.

## История (undo/redo)

- `node-editor/node-project/ProjectHistory.ts`. Снимок проекта: ноды по постоянному id (`WeakMap` нода → id) с настройками в JSON и связи вида `id.порт>id.порт`. Живые значения входов с проводом в снимок не попадают.
- Откат — это не перезагрузка проекта, а применение разницы (`utils/historyDiff.ts`, покрыта тестами):
  - удалить лишние ноды;
  - снять лишние провода;
  - восстановить изменившиеся настройки;
  - создать пропавшие ноды с прежними id;
  - подключить провода.

  Остальные ноды не пересоздаются, звук не прерывается.
- Шаг пишет `views/history/History.tsx`: когда отпустили мышь или клавишу, поменяли поле, плюс редкий запасной таймер. Пока кнопка мыши зажата, шаг не пишется. Пока идёт загрузка (`NodeProject.busy`), шаг откладывается. После открытия проекта при старте история сбрасывается.
- Изменения внутри блока откатываются через настройку `graph` у Group, то есть блок перезагружается целиком.

## Медиа (`library/media`)

- Файлы лежат в IndexedDB `w-nodes-media`, ключ — SHA-256 содержимого. Если IndexedDB недоступна, используется запасной вариант в памяти.
- Нода хранит ссылку `local:<hash>` в обычном `@store`-поле. `collectMediaRefs` находит все ссылки в конфигах, в том числе вложенные (внутри блоков).
- `AudioProject.exportData` вшивает файлы в таблицу `media`. Лимит зависит от назначения: файл — без лимита, буфер — 4 МБ, ссылка — 256 КБ, автосохранение — 0. `importData` проверяет хеш перед сохранением.
- Декодированные `AudioBuffer` кешируются. Неудача («нет файла») не кешируется: нода оживёт, как только файл появится.

## Блоки (`blocks/`)

- **Group** — нода со своим графом. Внутренний редактор (`<Editor nested>` + `GroupProject`) рендерится через портал в `div` у `body`. Он смонтирован всегда, поэтому звук внутри работает и при закрытом блоке; «Open block» просто показывает этот слой.
- **Порты блока — слоты** `{ id, kind, label }`. У каждого слота два `GainNode`: внешний (`outerGain`) — порт Group, внутренний (`innerGain`) — порт ноды Group Input или Group Output. Без компиляции их соединяет мост (вход: внешний → внутренний, выход: внутренний → внешний), так что звук идёт как через один общий узел. Мосты ведёт `Routing` (`routing.ts`). Слоты хранятся в самой Group (`@store slots`): тогда порты появляются раньше, чем загрузится внутренний граф, и внешние связи восстанавливаются.
- **`graph`** — это `@store`-аксессор. Геттер сериализует внутренний проект, сеттер загружает его. Пока граф грузится, геттер отдаёт ожидающие данные, так что данные не теряются.
- **Сворачивание** (`actions.ts`): выделение сериализуется. Каждая связь наружу превращается в слот и пару «Group Input/Output ↔ порт ноды». Выделение удаляется, создаётся Group, внешние провода переподключаются к её портам. Разворачивание делает обратное.
- Внутренний проект — простой `NodeProject`, а не `AudioProject`: иначе получается цикл импортов `_nodes → Group → AudioProject → _nodes`.

### Компиляция блоков

Переключатель **Compiled** на лице блока (`@store compiled`). Если внутри только «чистые» ноды, весь граф блока работает как один сгенерированный AudioWorklet, и петли получают задержку в 1 сэмпл, а не в квант Web Audio (128).

- **Компилятор** — `library/blockCompiler`, без Web Audio, покрыт тестами. На входе граф блока (`nodes`, `connect`, `configs`), на выходе `{ ok: true, source, inputs, outputs, params, passthrough }` или `{ ok: false, reason }`.
- **Шаблоны нод** (`templates.ts`): карта портов в порядке `sortPorts`, структурные поля и кусок кода. Вход в карте — ключ `@store` с `SignalNode`, его значение берётся, пока к входу нет провода. Поддерживаются Math, Expression, Memory, Slider, Toggle, LFO, ADSR, Counter, Random, Group Input и Group Output. Любая другая нода (и вложенный блок) — отказ «X is not compilable».
- **Порядок** — обход в глубину от выходов блока; ноды, которые не доходят до выхода, не считаются. Провод к ноде, которая ещё на стеке обхода, — обратная связь: он читает значение этой ноды с прошлого сэмпла (`s.d<n>`). Порядок детерминирован, от номеров нод.
- **Значения без провода** не вшиваются в код, а становятся параметрами процессора (`k0`, `k1`…). В параметр подаётся `ConstantSourceNode` самого `SignalNode`, поэтому ручки и Slider работают без перекомпиляции. Перекомпиляция (с паузой 250 мс) нужна только при смене структуры: нод, проводов, слотов и структурных полей (операция Math, формула Expression, форма LFO, слот).
- **Слот — отдельный вход или выход процессора** с одним каналом. Это проще, чем каналы одного входа: нет лимита каналов, маршрутизация — обычный `connect(node, 0, k)`. Вход сводится в моно так же, как у `AudioParam`, а внутри блока все ноды и так моно. Group Input, соединённый прямо с Group Output, идёт мимо процессора и сохраняет стерео.
- Значения на проводах округляются до float32 (`Math.fround`), как в Web Audio. Math использует ту же таблицу операций (`library/math`), модуляция — `library/modulation`.
- **Безопасность.** В исходник попадают только шаблоны, `toString()` таблиц `library/math` и `library/modulation`, вывод codegen `library/expression` и номера. Операция Math и форма LFO сверяются со своими списками, id слотов в код не попадают. Перед запуском `checkPorts` (`blocks/ports.ts`) сверяет порты живых нод с картой компилятора.
- **Запуск** (`blocks/program.ts`): новая программа подключается, потом мосты снимаются, потом снимается старая программа. Если сборка не удалась, блок звучит своими нодами, а причина видна на лице блока.
- **Ограничения.** Внутренние ноды остаются смонтированными и могут продолжать считать, хотя их выход никуда не идёт, так что CPU пока не экономится. При перекомпиляции состояние (Memory, фаза LFO) сбрасывается. Каждая новая структура регистрирует новый модуль worklet'а.

## Как добавить ноду

1. Создайте `src/components/audio-context/nodes/MyNode.tsx` по образцу выше. Выберите уникальный `@name`, `@group` из `_groups.ts` и значок из `lucide-react`.
2. Добавьте класс **в конец** массива в `_nodes.ts`.
3. Если нужна своя DSP-логика, напишите worklet через `defineWorklet` по образцу `worklet/*.ts`.
4. Чистую логику (без Web Audio) положите в `src/library/…` и покройте тестом в vitest.
5. Проверка: `npx tsc --noEmit -p .`, `npm test`, `npm run build`. Потом руками в `npm run dev`: нода создаётся, копируется (Ctrl+C/V) и переживает перезагрузку страницы.
